# KCMS Design Kit — 개발자 인수인계

이 문서 하나만 읽고 시작할 수 있게 썼습니다. 규칙과 API 계약은 [rules.md](rules.md),
보이는 모습은 [components.html](components.html), 새 화면 뼈대는
[template.html](template.html) 에 있습니다.

---

## 1. 5분 만에 시작하기

1. zip 을 풀고 `template.html` 을 브라우저에서 그냥 엽니다. GNB·레일·작업 탭·검색 필터·
   표·페이징·모달이 그대로 동작합니다.
2. 그 파일을 복사해 새 화면을 만듭니다. 바꿀 곳마다 주석이 붙어 있습니다.
3. 컴포넌트가 필요하면 `components.html` 에서 찾아 **코드** 버튼 → **복사** 로 마크업을
   가져옵니다. 화면에 그려진 것과 같은 마크업이라 문서와 실제가 어긋나지 않습니다.

불러오기 순서는 `rules.md` §5 **불러오기** 에 있습니다. 두 가지만 기억하면 됩니다.

- **Pretendard 웹폰트를 반드시 불러옵니다.** 빠지면 페이징의 `« ‹ › »` 글리프 모양이 달라집니다.
- **`modal-overrides.css` 는 `common.css` 다음에.** 순서가 바뀌면 공통 모달의 표 헤더가 어긋납니다.

## 2. 반드시 지켜야 할 것 넷

### ① 색은 hex 로 적지 않습니다

`tokens.css` 에 hex 로 적힌 색은 **7개뿐**이고, 나머지는 전부 이 7개를 `color-mix` 로
섞어 만듭니다. 그래서 뿌리 하나를 바꾸면 그 계열이 통째로 따라옵니다.

```css
/* O */ color: var(--txt);
/* O */ background: color-mix(in srgb, var(--pb) 8%, #fff);
/* X */ color: #333;
```

새 색이 필요하면 **뿌리를 늘리지 말고** 기존 뿌리에서 농도를 조절하세요. 어떤 토큰이
있는지는 디자인 시스템 문서의 **색** 섹션에서 실제 값과 함께 볼 수 있습니다.

### ② SVG 의 `stroke`/`fill` 속성에는 CSS 변수가 안 먹습니다

```html
<!-- X 검게 그려집니다 -->
<svg stroke="var(--gnb)">
<!-- O 부모의 color 를 따릅니다 -->
<svg stroke="currentColor">
```

전에 이걸로 아이콘 37개가 한꺼번에 검게 나온 적이 있습니다.

### ③ `build-css.py` 를 다시 돌리지 마세요

`common.css` 를 처음 뽑을 때 쓴 **기록용** 스크립트입니다. 추출 이후 손으로 반영한 것
(글자 크기 12px 통일, 토스트, 알림 배너, 색 토큰화, 표 도구)이 전부 지워집니다.
화면이 바뀌면 바뀐 부분만 `common.css` 에 옮기세요.

### ④ 화면 전용과 공통을 구분합니다

- 두 개 이상 화면이 쓰면 → `common.css` (= kit)
- 한 화면에서만 쓰면 → 그 화면의 `<style>`

`styles/screen-specific.css` 는 체험판 화면을 그대로 재현할 때만 쓰는 **참고용** 모음입니다.
기본으로 불러오지 마세요.

## 3. kit 에 컴포넌트를 추가하는 절차

이 kit 은 입학관리 5개 화면에서 뽑았습니다. 수납회계·시간표·출결처럼 성격이 다른 메뉴를
만들면 여기 없는 것이 나옵니다(금액 입력, 시간표 격자, 출결 체크 격자 등). 그때
**각자 만들어 쓰면 두 달 뒤에 같은 컴포넌트가 다섯 벌**이 됩니다. 아래 순서로 올려 주세요.

1. **먼저 찾습니다.** `components.html` 에서 Cmd+F. 비슷한 것이 있으면 그것을 씁니다.
   (예: 라벨-값 폼은 새로 만들지 말고 `table.infotbl`)
2. **한 화면만 쓰면 그 화면에 둡니다.** 두 번째 화면이 같은 것을 필요로 할 때 올립니다.
3. **올릴 때 같이 하는 것 네 가지**
   - `common.css` 에 규칙 추가 (색은 토큰으로)
   - `components.html` 에 데모 한 줄 추가 — 코드 버튼은 자동으로 붙습니다
   - `rules.md` 에 규칙 한 줄 (금지 사항이나 크기 기준이 있으면)
   - JS 가 필요하면 `js/` 에 파일 추가 + `rules.md` §5 계약에 서명 추가
4. **이름 규칙** — 기존 계열 이름을 따릅니다. 표는 `table.xxx`, 배지는 `.xxxbadge`,
   모달은 `#xxxModal`. 같은 역할에 새 클래스명을 만들지 않습니다
   (`.tharrow` 가 있는데 `.sortArrow` 를 만들지 않는 식).

**리뷰어를 한 명 정해 두세요.** 컴포넌트 추가 PR 을 그 사람이 보는 것만으로 난립을 막을 수
있습니다. 이 kit 이 흐트러지는 가장 흔한 경로가 "급해서 그냥 만들어 씀" 입니다.

## 4. 알려진 한계 — 미리 알고 시작하세요

| 항목 | 내용 | 어떻게 |
|---|---|---|
| **범위** | 입학관리 5개 화면에서 뽑았습니다. 다른 메뉴가 필요로 할 컴포넌트는 아직 없습니다 | §3 절차대로 채워 나갑니다 |
| **웰컴 SMS 화면** | 그 화면만 Tailwind 기반이라 이 시스템 밖입니다. kit 클래스를 하나도 쓰지 않습니다 | 그 화면을 손보게 되면 kit 으로 다시 만드는 편이 낫습니다 |
| **인쇄·성적표 새 창** | `window.open` 으로 뜨는 별도 document 라 앱의 `:root` 가 닿지 않습니다 | 각 문서가 **자기 `:root`** 를 갖고 있습니다. 그 안에서 토큰을 쓰세요. 값을 바꾸려면 그 `:root` 도 함께 고쳐야 합니다 |
| **`.btn.danger`** | 빨간 버튼이 아닙니다. 삭제 버튼에 빨강을 쓰지 않기로 해서 흰 바탕 + 중립 테두리로 나옵니다 | 빨강은 삭제 아이콘 hover 에만 남습니다 |
| **`.btn.green`** | 반 생성 모달 한 곳에 있는 화면 전용 클래스라 kit 에 없습니다 | kit 만 불러 쓰면 `.g` 모양으로 떨어집니다 |

## 5. 자주 걸리는 것

- **모달을 열었는데 셀렉트가 네이티브로 보입니다** → 모달은 나중에 만들어져 초기
  `initLayout()` 한 번으로는 안 잡힙니다. `KCMS.initCsel(root)` 를 그 안에서 다시 부르세요.
- **표가 컨테이너를 넘쳐 가로 스크롤이 생깁니다** → `colgroup` 의 모든 `col` 에 폭을 줬을
  때입니다. 남는 폭을 먹는 열 하나는 폭을 비워 두세요.
- **`input[type=date]` 가 "2026. 08. 30." 으로 나옵니다** → 네이티브 입력을 그대로
  노출하면 브라우저가 로캘 형식으로 직접 그립니다. 보이는 칸은 `type="text"` 로 두고
  숨은 `.dateshadow` 를 짝지어 쓰세요(`template.html`·`memo-modal.js` 참고).
- **팝업 안 검색줄이 흰 바탕에 있습니다** → 검색줄은 `.modal-body` **밖**, `.modal-box`
  위에 둡니다. `.modal-box` 가 회색이라 자연히 회색 띠가 됩니다.
- **`KCMS.pct(0.734)` 가 `0.7%` 로 나옵니다** → `pct()` 는 이미 백분율인 수를 받습니다. `73.4` 를 넘기세요.
