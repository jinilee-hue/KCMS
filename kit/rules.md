## 0. Kit 의 범위

**입학관리 GNB 3뎁스 메뉴 5페이지와 그 안에서 열리는 모달까지**입니다.

| 카테고리 | 화면 |
|
**데모에 넣는 라벨과 클래스는 화면에 실제로 있는 조합만 씁니다.**
보기 좋으라고 "닫기"에 파랑을 입히거나 없는 라벨을 지어내면, 그 조합이 표준으로 굳어집니다.
새 예시가 필요하면 화면에서 그 조합을 먼저 찾습니다.

---|---|
| 예비생 대시보드 | 예비생 대시보드 (ET-01-001) |
| 예비생 관리 | 예비생 등록·관리 (ET-02-012) · 설명회 예약자 현황 (ET-02-010) |
| 진학생 관리 | 진학생 관리 (ET-04-001) |
| 신학기 학급편성 | 반편성 배치관리 (ET-05-001) |

모달은 SMS 발송 · SMS 발송내역 · 학생메모 · 담당자 찾기 · MAP 성적표와
각 화면이 자체로 띄우는 팝업입니다.

**이 범위 밖 화면에서만 쓰는 컴포넌트는 Kit 에 싣지 않습니다.** 다른 메뉴(학생관리 등)나
메뉴에서 내린 화면의 것을 데모에 올리면, 쓰지 않는 규격을 표준으로 착각하게 됩니다.

## 1. Do / Don't

| 영역 | 이렇게 | 이러지 않기 |
|---|---|---|
| 색 | 토큰 변수만 사용 `var(--pb)` | hex 하드코딩 · 새 파랑 추가 |
| 지표 색 | 그래프는 톤다운, 글자는 원색 | 넓은 면적에 원색 · 작은 글자에 톤다운 |
| 차트 | 브랜드 파랑 농도로 구분 | 빨강·주황·초록 (기준 미달 경고만 예외) |
| 배지 | 굵기 500 · 용도별 클래스 | 굵기 700 · 아무 배지나 재사용 |
| 삭제 버튼 | 되돌릴 수 없는 동작만 빨강 | 행 삭제 · 탭 닫기에 빨강 |
| 토스트 | 배경색으로 상황 구분 · 순수 텍스트 | 좌측 액센트 바 · 이모지 |
| 탭 | 상위·하위는 밑줄, 토글은 채움 | 상·하위를 같은 모양으로 |
| 날짜 | 하이픈 `2026-08-27` | 점 `2026.08.27` |
| 타이포 | 8단계 안에서 선택 · 강조는 굵기로 | 새 크기 추가 · 본문 키워 강조 |
| 달력 | 오늘 채움 / 선택 링 · 파랑 한 가지 | 오늘·선택에 서로 다른 파랑 |

## 2. 컴포넌트별 금지 · 원칙

| 컴포넌트 | 규칙 |
|---|---|
| 타이포 | 크기 단계를 늘리지 않는다 (6단계 고정) |
| 간격 · 라운드 | 토큰에 없는 새 값을 만들지 않는다 |
| 그림자 | 카드 · 패널 · 표에 그림자 금지 — 구분은 1px 테두리 |
| 아이콘 | 채움(fill) 아이콘 금지 — 선 아이콘 `currentColor` |
| 탭 | 상위 · 하위 · 토글 **세 모양이 서로 달라야 한다** |
| 하위 탭 | 컨테이너 배경 금지 (알약 버튼만) |
| 토글(`.seg`) | 탭이 아니라 값 전환 · **버튼 사이 구분선 없음**(gap 0 · 활성 버튼만 파랑 채움 + 라운드 6px) |
| 배지 | 굵기 700 금지 (500 고정) |
| 폼 | 포커스 링 · 그림자 금지 — 테두리 색만 바뀐다 |
| 검색폼 칸선 | `.hascell` 클래스로 준다 — `td:has(.fselect)` 처럼 컨트롤 종류로 잡지 않는다 |
| 트리(다중) | 단일 선택에 쓰지 않는다 · 전부 체크 = 전체(제한 없음) |
| 트리 카운트 | 장식용 숫자 금지 — 실제 값만. 세는 칸이 다르면 숫자도 달라야 한다 |
| 날짜 · 달력 | 파랑 두 가지 금지 — 오늘은 채움, 선택은 링 |
| 모달 | 본문에 테두리 없음 (흰 박스) |

## 3. 컴포넌트별 상세 규칙

### 색 — 기본색 7개에서 전부 파생됩니다

`tokens.css` 에 **hex 로 적힌 색은 7개뿐**입니다. 나머지는 전부 이 7개를 `color-mix` 로
섞어 만듭니다. 그래서 뿌리 하나를 바꾸면 그 계열이 통째로 따라 바뀝니다.

| 뿌리 | 값 | 무엇의 뿌리인가 |
|---|---|---|
| `--pb` | `#0066FF` | 본문 강조 · 선택 · 표 상단 라인 · 그래프 |
| `--gnb` | `#2C3E5A` | 상단바 · 테두리 · 페이지 배경 |
| `--txt` | `#1f2937` | 본문 글자 · 섹션 제목 |
| `--danger-root` | `#e5484d` | 위험 — 배지 · 경고 글자 · 삭제 hover |
| `--ok-root` | `#1a7a3c` | 정상 · 완료 |
| `--warn-root` | `#f97316` | 주의 |
| `--accent-pink` | `#ff3b8d` | 그래프 보조선 1곳 |

**규칙 — 새 색을 hex 로 추가하지 않습니다.** 필요한 농도는 뿌리에서 섞어 씁니다.
진한 단계는 검정을, 옅은 단계는 흰색을 섞습니다.

```css
/* O */ color: color-mix(in srgb, var(--danger-root) 72%, #000);
/* X */ color: #a3252a;
```

상태색 세 계열은 이렇게 짜여 있습니다. **투명도만 다른 것은 같은 색 1종으로 셉니다.**

| | 진한 쪽 | 기준 | 옅은 배경 |
|---|---|---|---|
| 위험 | `--danger-deep` `--danger-txt` | `--danger` | `--danger-tint` `--danger-bg` |
| 정상 | `--ok-deeper` `--ok-deep` | `--ok` | `--ok-light` |
| 주의 | — | `--warn` | `--warn-light` |

`rgba()` 는 `var()` 를 받지 못해 `--pb-a08` `--pb-a15` `--gnb-a92` 세 개만 예외로
같은 색을 알파만 달리해 따로 둡니다. 이 셋은 **뿌리를 바꿔도 따라오지 않습니다.**

화면·kit 안에 hex 로 남아 있던 60곳은 2026-08-30 에 모두 토큰으로 바꿨습니다.
남은 예외는 두 가지뿐이고, 둘 다 이유가 있습니다.

| 예외 | 곳 | 왜 |
|---|---|---|
| 인쇄·성적표 새 창(`.lcx-*` `.rpt-*`) | 36 | `window.open` 으로 뜨는 **별도 document** 라 앱의 `:root` 가 닿지 않습니다. 인쇄물이라 테마와 무관한 고정색이 맞습니다 |
| 웰컴 SMS 화면의 Tailwind 그라디언트 | 3 | 직원용 업무 화면이 아니라 학부모가 문자 링크로 여는 **모바일 랜딩**입니다. 이 kit 의 대상이 아닙니다 |

SVG 의 `stroke`/`fill` **속성**에는 CSS 변수를 쓸 수 없습니다(`stroke="var(--gnb)"` 는
검게 그려집니다). 아이콘 색은 `currentColor` 로 두고 부모의 `color` 로 정하세요.

#### 색 — 지표

기준선이 있는 지표(충원율 70% · 가동률 30%)는 **두 가지로만** 가릅니다.

| | 면적이 넓은 그래프 · 진행바 | 면적이 좁은 글자 · 아이콘 |
|---|---|---|
| 기준 이상 | `--chart-ok` 톤다운 파랑 | `--pb` 원색 |
| 기준 미만 | `--chart-low` 톤다운 레드 | `--danger` 원색 |

### 서체 — Pretendard 를 반드시 불러옵니다

모든 화면은 `<head>` 맨 위에서 Pretendard 를 받아옵니다. 이 한 줄이 빠지면 한글은 시스템 서체로
떨어지고, 페이징의 `« ‹ › »` 같은 기호 글리프가 실제 화면과 다른 모양(좁고 굵은 형태)으로 그려집니다.

```html
<link rel="preconnect" href="https://cdn.jsdelivr.net">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/pretendard@1.3.9/dist/web/static/pretendard.min.css">
```

`body{font-family:Pretendard,…}` 스택만으로는 부족합니다 — 웹폰트를 실제로 내려받아야 합니다.

### 컴포넌트별 고정 글자 크기

16개 화면 전수 확인(2026-08-27)으로 아래 값이 **모든 화면에서 동일**합니다. 새로 만들 때도 이 값을 씁니다.

| 크기 | 굵기 | 쓰는 곳 |
|---|---|---|
| 13px | 700 | 모달 제목 · 섹션 제목 `.sectit` |
| 12px | 500 | 버튼 `.btn`(작은 버튼 포함) · 상위 탭 `.ptab` |
| 12px | 400 | 페이징 `.pgnum` `.pgnav`(활성만 700) · 경로바 `.bcbar` · 작업 탭 `.wtab` |
| 12px | 700 | 표 헤더 `th` · 세로형 표 라벨 · 필터 라벨 `.flabel` · 토글 `.seg` |
| 12px | 400 | 표 셀 `td` · 입력 `.finput` · 셀렉트 `.fselect` · 커스텀 셀렉트 `.csel-box` · 트리 `.ctree-box` |
| 11px | 400 | 섹션 제목 옆 보조 설명 `.hint` · 트리 카운트 |
| 10.5px | 500 | 배지 `.badge` · 상태 알약 `.statuspill` |

> 예외는 **예비생 대시보드(01-001)** 뿐입니다 — 지표 화면이라 제목 17px · 큰 수치 34px 등 자체 스케일을 씁니다.

### 타이포


- 크기 단계를 새로 만들지 않습니다 — 8단계 안에서 고릅니다.
- 강조는 **굵기**로 합니다. 본문 크기를 키워 강조하지 않습니다.
- 줄간격은 본문 1.5 · 설명문 1.7. 표 안은 줄간격 없이 셀 높이(24px)로 맞춥니다.
- 굵기 800 은 지표 수치만. 그 외 강조는 700 까지입니다.

### 여백 · 간격

```
섹션 제목      위 12px · 아래 8px
패널           안쪽 14px · 패널끼리 세로 12px
콘텐츠 기준선   좌우 73px (밴드는 화면 끝까지, 안쪽 여백 14px)
액션바 ↔ 표     6px          표 ↔ 페이징     8px
```

### 탭 — 어떤 걸 쓸지

| 상황 | 쓰는 것 |
|---|---|
| 내용 자체가 다른 화면으로 바뀐다 | 밑줄 탭 |
| 같은 화면에서 목록을 나눈다 | 알약 탭 |
| 값을 바꾸거나 조건을 켠다/끈다 | 토글 (붙은 박스) |

**밑줄 탭은 한 규격입니다** — 여백 `9px 14px` · 12px / 700 · 선택은 진파랑 글자 + 밑줄 3px.
브레드크럼 아래에 놓이든(`.ptab`) 카드 안에 놓이든(`.dtab`) 탭 자체는 같고,
자리는 감싸는 상자(`.pagetabs` / `.dtabs`)가 정합니다.
(2026-08-30 통일: `.ptab` 이 `10px 16px`·`12.5px` 로 따로 놀아 높이가 37px 대 35px 로 갈렸습니다)

### 셀렉트 — 언제 무엇을

| 종류 | 언제 |
|---|---|
| **커스텀 셀렉트 (기본)** | 화면의 모든 `<select>` — `initLayout()` 이 자동으로 바꿉니다 |
| 체크박스 트리 `.ctree` | 값에 계층이 있고 여러 개를 고를 때 (현재 레벨 · 현재 학급) |

박스 모양은 둘 다 같습니다(24px · 라운드 3px · 오른쪽 v 화살표). 다른 건 열렸을 때의 목록뿐입니다.
목록은 박스 폭에 맞추고(최소 240px), 오른쪽 여유가 없으면 박스 오른쪽 끝 기준으로 펼칩니다.

**네이티브 `<select>` 는 5페이지에 하나도 없습니다**(실측) — 페이지당 개수까지 전부 커스텀으로 바뀝니다.
계층을 하나만 고르는 트리(`.tsel`)도 쓰는 곳이 없어 Kit 에서 내렸습니다.

비활성은 `select` 에 `disabled` 만 주면 됩니다 — 래퍼에 `.csel-disabled` 가 붙어
회색 배경이 되고 열리지 않습니다(진학생 관리에서 씁니다).

표 안 인라인 편집 셀렉트는 **표 밖 셀렉트와 사실상 같습니다**(실측) —
높이·배경·테두리·라운드·글자 크기가 모두 같고 왼쪽 여백만 3px 좁습니다(8px → 5px).
그래서 데모에 따로 싣지 않습니다.

클래스가 `.csel.h22` 지만 **실제 높이는 24px** 입니다 —
2026-08-28 컨트롤 높이 통일이 덮어씁니다. 이름과 값이 어긋나 있으니 22px 로 읽지 마세요.

### 표 — 정렬

`th.sortable` 을 누르면 그 열로 정렬하고, 다시 누르면 방향이 바뀝니다.

화살표(`.tharrow`)는 정렬 가능한 열이면 **늘 보입니다** — hover 로 나타났다 사라지면
누를 수 있는 자리인지 알 수 없고, 자리도 흔들립니다.

| 상태 | 클래스 | 모양 |
|---|---|---|
| 기본 | `.tharrow` | ▾ · 진회색 `--gnb` |
| 내림차순 | `.tharrow.on` | ▾ · 파랑 `--pb` |
| 오름차순 | `.tharrow.on.up` | ▾ 를 `rotate(180deg)` · 파랑 |

**글리프는 `▾` 하나뿐입니다.** 방향은 `.up` 의 회전으로 표현합니다 —
`▴`·`▲` 는 본문 폰트(Pretendard)에 없어 다른 폰트로 폴백되면서 `▾` 보다 크게 그려집니다.
정렬을 걸면 그 열 화살표만 커 보이던 원인이었습니다.

크기는 **16×16 박스 · `font-size:13px`** 로 목록·모달·불러오기 표가 모두 같습니다.
표마다 다른 클래스(`.sarrow`·`.sortArrow`)를 만들지 말고 `.tharrow` 하나를 씁니다.

정렬과 열 너비 조절은 `js/table-tools.js` 가 담당합니다. 화면마다 다시 짜지 않습니다.

```html
<th class="sortable" data-k="name">학생명<span class="colresize" data-k="name"></span></th>
```

`.sortable` 이 붙은 th 는 눌러서 정렬, 안에 든 `.colresize` 는 끌어서 폭 조절입니다.
라벨을 `.thwrap`/`.thlabel` 로 감싸고 `▾` 버튼을 붙이는 것은 `initSort()` 가 합니다 —
마크업에 직접 적지 않습니다. **정렬 비교는 화면이 합니다**(`onSort` 콜백).

### 표 — 스크롤 정책

**스크롤은 언제나 표를 감싼 `.tblwrap` 이 합니다.** 페이지(문서)는 스크롤하지 않습니다 —
앱 셸이 `100vh` 이고 `.content` 가 `overflow:hidden` 이라, 목록이 길어져도 늘어나는 것은 표 영역뿐입니다.
(실측: 진학생 관리 30행 목록 = 표 912px 가 458px wrap 안에서 스크롤, 문서 스크롤 없음)

| 경우 | 처리 |
|---|---|
| 세로 | 감싼 박스가 스크롤. **헤더(th)와 그 위 파란 선까지 고정**되고 `td` 만 움직인다 |
| 가로 | 같은 `.tblwrap` 이 담당 — 카드·모달이 가로로 늘어나지 않게 |
| 가로 · 세로 동시 | 한 컨테이너가 둘 다 처리하고, 헤더는 세로 스크롤에서만 고정 |

보드형(반편성)도 같은 규칙입니다.

| 뷰 | 스크롤 컨테이너 |
|---|---|
| 통합 배치표 | `.matwrap` 하나가 가로·세로 |
| 학생 리스트 | `.board` 하나가 가로·세로 (바깥 `.boardwrap` 은 스크롤하지 않음) |

**스크롤 컨테이너는 한 겹만 둡니다.** 겹치면 막대가 두 개 생깁니다 — 학생 리스트 뷰가 그랬습니다.
`overflow` 는 한 축만 `visible` 로 둘 수 없다는 점도 함께 기억해 두세요(`visible + auto` → 둘 다 `auto`).

막대 모양은 축마다 다릅니다(`overlay-scroll.js`).

| 축 | 막대 | 이유 |
|---|---|---|
| 세로 | 표 **안에 떠 있는** 6px 막대 (`rgba(44,62,90,.28)`) · 헤더 아래에서 시작 | 자리를 차지하지 않아 열 너비가 밀리지 않는다 |
| 가로 | 표 **아래 기본 막대** 8px — 숨기지 않는다 | 어디까지 밀렸는지 늘 보여야 하고, 아래는 가릴 내용이 없다 |

표가 아닌 영역(모달 본문·패널)에 같은 막대를 쓰려면 **`.pcms-ovscroll`** 을 붙입니다.
`.ovscroll` 은 SMS 발송 모달이 선점한 이름이라, 그대로 쓰면 그쪽 `pointer-events:none` 이
함께 걸려 표의 휠·클릭이 막힙니다.

크롬 함정 둘 — `::-webkit-scrollbar:vertical` / `:horizontal` 은 더 이상 적용되지 않습니다
(방향 없는 `::-webkit-scrollbar` 에서 `width` = 세로 폭, `height` = 가로 높이).
그리고 `scrollbar-width` 가 지정돼 있으면 `::-webkit-scrollbar` 규칙 전체가 무시됩니다.

행 수는 **페이징으로 끊습니다**(기본 30건) — 무한 스크롤은 쓰지 않습니다.
모달 안 표도 같은 규칙이고, 모달 본문이 아니라 `.tblwrap` 이 스크롤합니다.

### 배지

Kit 범위 5페이지와 그 모달에서 실제로 쓰는 배지는 **4가지**입니다(2026-08-29 실측, 모달을 연 상태 포함).
새 배지를 만들지 말고 이 안에서 고릅니다.

| 톤 | 값 | 쓰임 | 클래스 |
|---|---|---|---|
| 회색 채움 | `--bg` + `--txt-mut` | 남은 날짜(D-day) 등 눈에 띌 필요가 없는 값 | `.ddaybadge` |
| 파랑 틴트 | `--pb-light` + `--pb-dark` | 건수 · MAP 대상 | `.cntbadge` `.agebadge.mapin` |
| 레드 틴트 | `--danger-bg` + `--danger` | 남은 자리(TO) | `.tobadge.open` |
| 레드 채움 | `--badge-danger` + 흰 | GNB 탭의 NEW | `.tabbadge` |

공통 규격은 **10.5px / 500 · 높이 16px · 라운드 999px** 입니다.

범위 밖 화면에는 흰 배경(`.badge.has`) · 파랑 채움(`.mapbadge.brand`) · 진회색 채움(`.qbadge`) ·
고르는 칩(`.tag2`) · 달력 칸 태그(`.rcal-cell .tag`)가 더 있지만, 5페이지에서 쓰지 않으므로 Kit 에 싣지 않습니다.

### 세로형 표 — 줄 높이

한 줄 칸은 **33px** 로 맞춥니다(패딩 대신 행 높이 + `vertical-align:middle`).
다만 **여러 줄 입력(textarea)이 든 칸은 예외** — 위아래 4px 패딩을 돌려주고 높이는 내용에 맡깁니다(행 68px).
패딩을 0 으로 두면 특이사항처럼 여러 줄이 들어가는 칸이 위아래로 붙어 보입니다.

### 폼 — 규격

컨트롤은 **어디서나 24px** 입니다 — 표 안 인라인 편집 · 페이징 · 탭 알약 · 기간 탭까지 한 값입니다(2026-08-28 통일).
높이가 다른 것은 성격이 다른 셋뿐입니다 — 토글 스위치 18px · 체크/라디오 14px · 토글(.seg) 안쪽 버튼 20px(24px 박스 안 1px 여백).

```
버튼 · 입력 · 셀렉트 · 트리 · 날짜 · 검색상자 · 세그먼트   24px
표 안 인라인 편집(셀렉트·입력) · 페이징 버튼 · 페이지 입력   24px
하위 탭(알약) · 기간 탭          24px
토글 스위치                    18px      체크 · 라디오   14px
라벨 .flabel  12 / 700 #2C3E5A · 필수 .req 빨간 별 · 도움말 .form-hint · 오류 .form-error
```

**기간 간편선택(1일 · 1주 · 15일 · 1달 · 전체)은 붙은 세그먼트가 아니라 떨어진 개별 버튼입니다**
— 4px 간격 · 24px · 라운드 3px · 테두리 1px · 글자 12px, 선택된 것만 파란 배경(2026-08-29 통일).
모달마다 `.qbtn` · `.shSeg button` · `.mcSeg button` 로 이름은 다르지만 모양은 하나입니다.

**표 상단 파란 라인은 1px 한 겹, 셀을 덮는 오버레이로 그립니다** — `::before` 를 좌우로 1px 씩
넘겨 깔아 th 세로 보더 끝을 덮습니다. 안쪽 그림자(`box-shadow: inset`)로 그리면 세로 보더가
라인 위로 1px 올라와 눈금처럼 보이고, 래퍼 `border-top` 과 함께 쓰면 2px 로 겹칩니다(2026-08-29 통일).

### 버튼

높이 **24px 한 가지** · 라운드 3px · 글자 12px/500 · **최소 폭 56px**(표 안 `.btn.sm` 제외).
`.btn.sm` 은 작은 버튼이 아니라 **좌우 여백만 좁힌 변형**입니다(패딩 10px→8px, 높이·글자는 같음).

화면에 실제로 나오는 모양은 **네 가지**입니다. 맨 오른쪽은 화면에서 쓰인 횟수입니다.

| 클래스 | 모양 | 쓰는 곳 | 쓰임 |
|---|---|---|---|
| `.btn` | 파랑 채움 | 그 줄의 주요 동작 — 검색 · 저장 · 등록 | 46 |
| `.btn.g` | 흰 바탕 + 회색 테두리 | 보조 동작 — 초기화 · 취소 · 닫기 | 85 |
| `.btn.s` | 네이비 채움 | 시스템 동작 — 일괄 처리 · 발송 | 7 |
| `.btn.g.xls` | `.g` + 초록 엑셀 아이콘 | 엑셀 다운로드 전용 | 7 |

`.btn.sm` 은 색이 아니라 좌우 여백만 좁힌 변형이라 위 네 개와 겹쳐 씁니다 — 표 안에서 59곳.

**`.btn.danger` 는 빨간 버튼이 아닙니다.** 삭제 버튼에 빨강을 쓰지 않기로 해서, 뒤쪽 규칙이
`background:#fff !important` 로 덮어 **`.btn.g` 와 같은 중립 흰 버튼**으로 나옵니다.
`.btn.danger.soft`(옅은 붉은 틴트) 도 같은 `!important` 에 걸려 똑같이 중립으로 떨어집니다 —
실측으로 둘 다 `bg #fff · color --txt · border --line` 입니다.
빨강이 남아 있는 곳은 **hover 때 붉어지는 삭제 아이콘**뿐입니다.
`.danger` 계열의 빨강 채움 규칙 4개는 아무 데도 그려지지 않는 죽은 코드입니다.

`.btn.green`(초록 채움)이 반 생성 모달 한 곳에 있지만 그 화면의 전용 CSS 라 **kit 에는 없습니다.**
kit 만 불러다 쓰면 `.g` 모양으로 떨어집니다.

| 종류 | 쓰는 곳 |
|---|---|
| 아이콘 포함 | 글자 앞에 11px 선 아이콘 — 검색 · 초기화 · 등록 · 수정 · 저장 · 엑셀 · 발송 |
| 아이콘 전용 | 부속으로만 씁니다 — 아래 높이 표 참고 |

아이콘 전용 버튼을 본문에 단독으로 두지 않습니다(화면에 그런 사례가 없습니다).
달력 아이콘은 `<rect x="3" y="5" width="18" height="16" rx="2"/><path d="M3 9h18M8 3v4M16 3v4"/>` · stroke 1.8 · 11×11 고정입니다.
한 줄에 여러 개면 **주요 1개 + 보조 여러 개**로 두고, 주요 버튼을 가장 오른쪽에 둡니다.


**추가·등록 버튼의 플러스는 SVG 아이콘 하나입니다** — 글자 `+` 를 앞에 붙이지 않습니다.
검색·초기화·Excel·저장이 이미 아이콘+텍스트라 결이 맞고, 글자 `+` 는 가로폭이 들쭉날쭉했습니다.
(2026-08-30 통일: 글자 8곳 → 아이콘, 이미 아이콘이던 5곳과 합쳐 13곳)

**컨트롤 높이는 24px 하나입니다** — 버튼 · 입력 · 셀렉트 · 페이징 · 알약 탭 모두.

예외는 **다른 컨트롤에 딸린 아이콘**뿐입니다. 혼자 서는 버튼이 아니라 부속이라
같은 높이를 주면 오히려 어긋납니다.

| 아이콘 | 크기 | 어디에 |
|---|---|---|
| `.ibtn` | 19×18px | 24px 입력 필드 **안**의 달력·검색 아이콘 — 24px 로 올리면 필드를 넘칩니다 |
| `.bcic` | 22×20px | 브레드크럼 바 안의 즐겨찾기·새로고침·닫기 묶음 |
| `.modal-x` | 20×20px | 모달 헤더(40px)의 닫기 |
| `.drangeclear` `.dclear` | 20×20px | 날짜 입력 옆 지우기 |
| `.wtnav` | 24×24px | 작업 탭이 넘칠 때 나타나는 좌우 이동 |
| `.tabnav` | 26×26px | GNB 메뉴가 넘칠 때 나타나는 좌우 이동 |

### 상태

- 포커스는 **테두리 색만** 파랑 — 링·그림자를 쓰지 않습니다(밀도 높은 표 화면에서 링은 시끄럽습니다).
- 비활성은 버튼이 `opacity:.45`, 입력·셀렉트가 회색 배경 `--bg` + 회색 글자 `--txt-mut` 입니다.
- 선택은 파랑 틴트 `--pb-light`, hover 는 그보다 옅은 `--pb-a08`.

### 날짜 필드 — 한 가지 폼

날짜 입력은 어디서나 같은 세 조각입니다.

```
[보이는 텍스트 입력 24px] + [숨은 input(type=date)] + [달력 버튼 .ibtn 19×18]
```

숨은 `input[type=date]` 는 브라우저 달력을 부르기 위한 것(1px, 눈에 보이지 않음)이고,
달력 버튼을 누르면 그 입력의 `showPicker()` 가 호출돼 화면 공통 달력 패널이 열립니다.
공통 모달들은 자체 이름(`.mcIwrap` · `.shIwrap` …)을 쓰고 있었는데, 2026-08-28 에 공통 클래스
(`.iwrap` · `.dateshadow` · `.ibtn`)를 함께 붙여 **한 규칙으로 잡을 수 있게** 했습니다.

### 날짜 · 달력

파랑은 `#0066FF` 한 가지만 씁니다. 오늘과 선택일의 구분은 색이 아니라 **형태**(채움 ↔ 링)입니다.
표기는 하이픈 `2026-08-27` — 점 표기는 쓰지 않습니다(`KCMS.date('20260827')`).

### 시간

`<input type="time">` 을 그대로 쓰고, `time-picker.js` 가 `showPicker()` 를 가로채
공통 패널(`.pcmstp`)을 띄웁니다. 브라우저 기본 시간 위젯은 페이지 CSS 로 모양을 바꿀 수 없어
화면과 따로 놀았습니다. 기본 시계 아이콘은 감춥니다.

패널은 날짜 피커와 같은 방침입니다 — 바깥선 없이 그림자, 라운드 3px, 고른 값만 파란 배경.
**오전 · 오후 → 시(01~12) → 분(5분 단위)** 순서이고, 취소 · 적용으로 닫습니다.

**키보드 직접 입력을 막지 않습니다.** 값은 `HH:MM`(24시간)으로 쓰고 `input`·`change` 를
발생시키므로, 섀도우 입력을 함께 쓰는 폼에서도 그대로 동기화됩니다.

### 모달

| 크기 | 값 | 쓰는 곳 |
|---|---|---|
| 안내 | `width:280px` → 실제 **320px**(`min-width`) | 짧은 알림 + [확인] |
| 입력 | `width:480px` | 메모·간단 등록 폼 |
| 기본 | `.modal-box` **640px** | 라벨-값 표가 들어가는 표준 폼 |
| 넓게 | `.modal-box.wide` **900px** | 검색줄 + 목록 표 |

헤더 40px · 본문은 흰 박스(테두리 없음) · 하단 버튼은 오른쪽 정렬(주요 버튼이 맨 오른쪽) · 드래그 이동 · `Esc`/오버레이 클릭으로 닫힘.
`.modal-box.sm` `.modal-box.lg` 같은 임의 규격은 쓰지 않습니다 — 실제 화면에 없는 값입니다.

공통 모달을 쓰려면 `styles/modal-overrides.css` 를 `common.css` **다음에** 불러야 합니다.
모달 스크립트가 자기 스타일을 함께 주입하는데, 화면에서는 그 위에 이 보정 규칙이 얹혀
표 헤더 톤·여백이 다른 팝업과 같아집니다(없으면 헤더 글자가 흰색으로 보입니다).

**공통 모달**은 화면마다 새로 만들지 않고 아래 스크립트를 불러 함수로 엽니다.

| 모달 | 파일 | 여는 함수 |
|---|---|---|
| 담당자 찾기 | `staff-pick-modal.js` | `openStaffPickModal({onApply})` |
| 상담이력 | `memo-modal.js` | `openMemoModal({studentNo, name, records, onChange})` |
| SMS 발송 | `sms-modal.js` | `openSmsModal({senderOptions, recipients, getAddCandidates, onSent})` |
| SMS 발송이력 | `sms-history-modal.js` | `openSmsHistoryModal({student, records})` |
| MAP 성적표 | `map-report-modal.js` | `openMapReportCard({studentName, standardLevels, subjects, totalRow, variant})` — 모달이 아니라 **새 창** |

DOM 은 처음 부를 때 한 번 만들어 두고 다시 씁니다. 화면에 미리 마크업을 넣지 않습니다.

**옵션의 전체 스키마와 레코드 필드는 각 파일 머리말 주석에 있습니다** — 이 표는 무엇을 넘겨야
하는지만 보여 줍니다. 아래 세 가지는 자주 걸리는 것이라 여기 적어 둡니다.

- `openMapReportCard` 는 `subjects` 만 넘기면 안 됩니다. `totalRow` 와 `standardLevels` 가
  없으면 표를 그리는 도중 예외가 나고 **창이 아예 열리지 않습니다**.
- `openMemoModal({records})` 와 `openSmsHistoryModal({records})` 는 배열을 **레퍼런스로** 들고
  있습니다. 모달 안에서 등록·수정하면 넘긴 배열이 그 자리에서 바뀝니다 — `onChange` 에서
  화면의 건수 배지를 다시 그리면 됩니다.
- `openSmsModal({getAddCandidates})` 는 "대상추가" 팝업이 부르는 **검색 함수**입니다.
  질의 문자열을 받아 후보 배열을 돌려주면 됩니다.

### 도움말(?) 팝오버

`.helpwrap > (.helpbtn + .helppop)` 로 두고 `KCMS.initHelpPop()` 이 배선합니다
(`initLayout()` 이 이미 부릅니다). 직접 짝을 지정하려면 `KCMS.wireHelpPop(btn, pop)`.

위치는 **버튼 아래 6px · 버튼 왼쪽 끝에서 왼쪽으로 10px** 이고 폭 320px 입니다.
`position:fixed` 로 띄웁니다 — 상세 패널(`.rbody`)처럼 `overflow:auto` 인 곳에서 잘리지
않게 하려는 것이라, CSS 로 `position:absolute`/`static` 을 덮어쓰지 마세요.
아래 공간이 모자라면 버튼 **위** 6px 로 뒤집습니다. 열려 있는 동안 버튼에 `.on` 이 붙습니다.
바깥 클릭 · ESC · 조상 스크롤에 닫힙니다.

### 토스트

배경은 **의미색 원색에 알파 70%**(`color-mix(in srgb, 색 70%, transparent)`)이고 글자·아이콘은 흰색.
`backdrop-filter` 는 쓰지 않습니다 — blur 를 걸면 뒤가 뭉개져 비침이 사라지고 균일한 흐린 색으로
보입니다(2026-08-30 요청으로 제거). 뒤 표·카드가 그대로 비쳐야 합니다.
테두리는 **채움과 같은 색을 투명도 없이 1px** — 흰색 반투명 선은 밝은 배경에서 거의 안 보여
상자 경계가 흐려집니다. 채움만 비치고 윤곽은 또렷하게 남깁니다.
왼쪽 액센트 바 없음, 문구에 이모지 없음. 최대 4개까지 쌓입니다.
타입을 생략하면 **neutral** 이고, 문구에 뚜렷한 단서가 있을 때만 올립니다.

| 문구 단서 | 타입 |
|---|---|
| 되었습니다 · 완료 · 성공 · 저장했 | success |
| 주세요 · 하세요 · 필수 · 확인해 | warning |
| 수 없 · 실패 · 오류 · 불가 | danger |
| 그 외 | neutral |

### 알림 배너 (`.msgbanner`)

토스트가 3.5초 뒤 사라지는 반면, 배너는 **그 자리에 남아야 하는 안내**입니다 —
저장 결과 · 중복검사 결과 · 전학 처리 안내처럼 폼 안에 붙습니다.

`.msgbanner` 단독으로는 여백·정렬만 있고 **배경도 테두리도 없습니다.**
반드시 변형 하나를 함께 붙이세요 — JS 로 켤 때도 `el.className = 'msgbanner ' + type` 처럼 넣습니다.

**토스트와 같은 4색 체계**입니다(2026-08-30). 다만 배너는 폼 안에 계속 남아 있으므로
토스트보다 훨씬 조용하게 칠합니다 — **채움 10% · 테두리 15% · 글자는 본문색(`--txt`) 하나**.
색이 옅어진 만큼 **성격은 아이콘이 나릅니다**(아이콘만 의미색 100%).

| 변형 | 아이콘 색 | 아이콘 | 언제 | 사용자가 할 일 |
|---|---|---|---|---|
| `.ok` | 녹색 `--ok` | ✓ | 저장·접수 완료 | 없음 |
| `.err` | 주황 `--warn` | ! | 입력 안내 — "필수값입니다" "확인해주세요" | **있음** (고쳐야 진행) |
| `.danger` | 빨강 `--danger` | ✕ | 실패·불가 — "삭제할 수 없습니다" | 없음(막힘) |
| `.neutral` | 파랑 `--pb` | ⓘ | 읽기만 하면 되는 참고 안내 | 없음 |

변형은 `guessType()` 분류를 그대로 따릅니다 — 어느 변형을 쓸지 헷갈리면 그 규칙을 보세요.
`.err` 이 빨강이 아닌 이유는 **"필수값입니다"가 실패가 아니라 조치 안내**이기 때문입니다.
실패·불가는 `.danger` 입니다.

**정보성 문구에 `.err` 를 쓰지 마세요.** 느낌표는 "고쳐야 진행된다"는 뜻이라, 참고 안내에 붙이면
읽는 쪽이 멈칫하고 진짜 경고의 무게도 같이 떨어집니다. 참고는 `.neutral` 입니다.

숨길 때는 `display:none`, 보일 때는 `display:flex` 입니다.

> 2026-08-24 에는 네 가지를 모두 Poly Blue 톤 하나로 묶어 "색으로 가르지 않는다"였습니다.
> 성격이 한눈에 안 보인다는 판단으로 2026-08-30 에 4색으로 되돌렸습니다.

문구 앞 **아이콘은 CSS(`::before`)가 그립니다** — 문구를 `textContent` 로 넣으면 자식 요소가
지워지므로 마크업으로 넣지 마세요. 토스트와 같은 모양이고 `mask` 로 그려 글자색을 그대로
따라갑니다. 크기 14px, 문구와 간격 `gap:6px`.

문구는 **왼쪽 정렬**입니다(`align-items:center` 는 세로 가운데일 뿐입니다). 가운데로 두는 건
"내용이 없다"는 안내(`.emptynote` · `.noresult` · `.noselect`)와 토스트(`.kt-body`) 쪽입니다 —
배너는 위쪽 입력 칸과 왼쪽 선을 맞춥니다.

## 4. 접근성 · 키보드

| 항목 | 규칙 |
|---|---|
| 키보드 | `Esc` 모달 · 달력 · 드롭다운 닫기 · `Tab` 이동 · `Enter`/`Space` 커스텀 셀렉트 열기 |
| 포커스 | 모달을 열면 첫 입력으로 포커스가 가고, 닫으면 열었던 버튼으로 돌아온다 |
| 역할 | 모달 `role="dialog" aria-modal="true"` · 토스트 `role="status"`(오류·경고는 `alert`) · 도움말 `role="tooltip"` |
| 아이콘 버튼 | 글자가 없으면 `aria-label` 필수 — 닫기 · 이전 · 다음 · 새로고침 |
| 대비 | 본문 `--txt` 12.6:1 · 보조 `--txt-mut` 6.4:1 · 파랑 위 흰 글자 4.6:1 |
| 모션 | `prefers-reduced-motion` 이면 토스트 · 차트 애니메이션을 끈다 |

새 화면은 **`template.html` 을 복사해서 시작하세요** — 위 순서와 셸 마크업이 이미 들어 있고,
그대로 열면 GNB·레일·작업 탭·검색 필터·표·페이징·모달이 동작합니다.

`modal-overrides.css` 를 빠뜨리면 공통 모달의 표 헤더 톤과 여백이 화면과 달라집니다.
순서가 중요합니다 — `common.css` 다음에 와야 보정 규칙이 얹힙니다.

`styles/screen-specific.css`(256 규칙)는 **한 화면에서만 쓰는 것들**이라 기본으로 넣지 않습니다.
체험판의 특정 화면을 그대로 재현할 때만 `common.css` 뒤에 덧붙이세요.

**셸 — GNB · 레일 · 작업 탭**

initLayout({ menu: PCMS_GNB_MENU, current: '입학관리',

**표 — 정렬 · 열 너비 조절**

```js
KCMS.initTableTools('table.grid', {
  sort:   { onSort: function(key, dir){ /* dir 은 'asc' | 'desc' — 정렬은 여기서 */ },
            initial: { key:'name', dir:'asc' } },

});
KCMS.initSort(table, opt);        // 정렬만
KCMS.initColResize(table, opt);   // 폭 조절만. opt.auto:true 면 th[data-k] 에 손잡이를 만들어 붙인다
```

`colgroup` 이 있으면 `<col>` 폭까지 함께 맞춥니다 — 없는 표도 그대로 동작합니다.

**셀렉트 · 트리 셀렉트 · 도움말 — 나중에 만든 DOM 에 다시 걸 때**

`initLayout()` 이 처음 한 번 걸어 주지만, 모달을 열거나 행을 새로 그린 뒤에는
그 안의 요소가 아직 배선되지 않았습니다. 그 부분만 다시 부릅니다.

```js
KCMS.initCsel(root);           // root 안 <select> → 커스텀 셀렉트
KCMS.syncSelectWidths(root);   // 옵션이 바뀌어 폭을 다시 재야 할 때
KCMS.initTreeSelect(root);     // 단일 선택 트리
KCMS.initCTree(root);          // 체크박스 트리
KCMS.initHelpPop(root);        // .helpwrap 의 ? 팝오버
KCMS.makeDraggable(box, handle);   // 모달 박스를 헤더로 끌어 옮기기
```

**포맷 — 표에 값을 넣을 때**

문자열은 **반드시 `esc()`** 를 거칩니다. 날짜는 하이픈, 전화는 `phone()` 하나로 통일합니다.

```js
KCMS.num(1284)             // '1,284'      문자열도 받습니다. null 은 ''
KCMS.pct(73.4, 1)          // '73.4%'      ★ 이미 백분율인 수를 받습니다. 0.734 를 넣으면 '0.7%'
KCMS.pctHtml(73.4, 1)      // '73.4<span class="pcts">%</span>'  % 만 작게
KCMS.date('20260812')      // '2026-08-12' '2026/08/12' 도 하이픈으로 바꿉니다
KCMS.date('20260812','/')  // '2026/08/12' 구분자를 바꿀 때만
KCMS.phone('01012341234')  // '010-1234-1234'
KCMS.mask('홍길동', 2)      // '홍길*'      앞 keep 글자만 남기고 나머지를 * 로. 기본 keep=1
KCMS.esc(s)                // HTML 이스케이프
```

**차트 — Chart.js 를 쓸 때**

색은 CSS 변수에서 읽어 옵니다. hex 를 직접 적지 않습니다.

```js
KCMS.setChartDefaults();         // 서체·격자·툴팁을 화면과 같게
KCMS.getChartColors();           // 6색 배열 — --pb 원색 + 투명도 5단계
KCMS.cssVar('--pb', '#0066FF');  // 토큰 하나 읽기. 두 번째 인자는 못 읽었을 때의 값
KCMS.ruleColor(73.4, 70);        // 기준 이상이면 파랑, 미만이면 레드 — 지표 규칙(§색) 그대로
```

`getChartColors()` 가 돌려주는 것은 **한 계열(파랑)의 농도 5단계**입니다. 계열이 다른 색을
섞지 않습니다 — 차트에 시맨틱 색(성공·경고·위험)을 쓰지 않는다는 규칙과 짝입니다.

**떠 있는 스크롤 막대**

파일을 불러오기만 하면 켜집니다 — 문서를 훑어 대상 표에 스스로 붙고, DOM 이 바뀌면
다시 훑습니다. 직접 부를 일은 거의 없습니다.

```js
PcmsOverlayScroll.scan(root);   // 새로 그린 영역만 다시 훑고 싶을 때
```

**토스트 문구 분류**

`KCMS.toast(msg)` 는 문구를 보고 색을 고릅니다. 직접 고르려면 두 번째 인자를 줍니다.
분류 규칙을 확인하려면 `KCMS.guessType(msg)` 가 같은 판단을 돌려줍니다.
